| NinjaTomoe.xbe | ryukenden (jp) | 5849 | D3D8 + D3DX8 + XGRAPHC | .text D3D D3DX XGRPH DSOUND XPP .rdata .data DOLBY | D3D 94 / 33，DSOUND 47，XAPI 39 |
| NinjaTrilogy.xbe | ryukenden (us) | 5849 | 同上 | 同上 | D3D 94 / 33，DSOUND 47，XAPI 39 |

四个附带程序都是**非 LTCG 的 D3D8**（函数边界完整、参数走栈），与 black-pc 原本支持的 BLACK 同类；主程序是 LTCG（寄存器传参、内联），地址表是手工核对的。

支持附带程序需要：
1. `XLaunchNewImage` → 以启动数据页重启加载器并装入目标 XBE（返回主程序同理）；
2. 每个 XBE 一个构建档案：SHA-256、库区段范围、D3D / DSOUND / XPP 函数地址表（由 XbSymbolDatabase 输出生成，调用约定按其签名）；
3. 逐个运行，按其 D3D 用法补 HLE（2D 模拟器类程序，预计以贴图 + 四边形为主）。

## 3. 加载器结构对附带程序的含义（2026-10-18）

`d3d/dispatch.cpp` `install_d3d_hooks` 只有两套：`profile.black`（black-pc 的 BLACK）与忍龙主程序（`kLayoutNgb` + `*_ngb` 表）。每套包括设备对象 / 渲染状态数组等全局地址（`g_layout`）、库函数清单（`kD3D` / `kDSound` / `kXpp`）与 HLE 表。附带程序每个都需要一套：全局地址可由 XbSymbolDatabase 的 VAR 给出；D3D 设备结构偏移随 XDK 版本变化（5659 与 5849 至少两套，与 BLACK 的版本是否一致待核）；外加 `XLaunchNewImage` 的进程重启与返回主程序。工作量估计为数天，结论可能是"支持 / 有限 / 不支持"。

## 4. 附带程序支持（2026-10-18 夜，进行中）

步骤与证据：
1. **函数表**：路线 A xboxrecomp 反汇编器（`python -B -m tools.disasm`，输出写入 `work/disasm_<名>/`，路线 A 目录无改动）+ XbSymbolDatabase → `tools/xbe_function_table.py` → `work/functions_<名>.csv`。D3D / DSOUND / XPP 函数数：Trilogy 272 / 345 / 208，FCJ 218 / 280 / 185。
2. **加载器表**：`ngb-recomp-native/tools/gen_aux_tables.py` 按名字把 BLACK 表、主程序输入表与额外表的 HLE 实现对到附带程序地址；普通 stdcall 的参数全走栈；只设寄存器后返回的库函数原生运行；单条 `jmp` 跳板沿用目标的实现。输出 `loader/src/auxtab/`（aux 是 Windows 保留设备名，git 无法收录）。
3. **构建档案**：`build_profile.h` 四个档案（SHA-256、初始化表、手柄描述、QPC 内的 rdtsc），`aux` 字段选表；设备对象 / push segment / 顶点常量缓冲在附带程序里不是固定地址，由加载器分配。
4. **新增 HLE**：内核 235 `NtWaitForMultipleObjectsEx`；`IDirectSoundBuffer_SetNotificationPositions`（混音时按播放位置触发事件，停止触发 OFFSETSTOP）；`D3DDevice_SetVerticalBlankCallback` / `SetSwapCallback` / `GetBackBuffer2`；`XInputPoll`；CPU 画的后缓冲（SNES 程序 `GetBackBuffer2` + `LockRect` 直接写像素，0 次 draw）在 Swap 前上传。
5. **XLaunchNewImage**：`HalReturnToFirmware(1/2)` 时读启动数据页的 `szLaunchPath`（`\Device\CdRom0;NinjaFCJ.xbe`），把页存到日志旁的 `.launchdata`，以同样参数（去掉 `--press`、日志改名 `<名>.<目标>.log`）带 `--launch-data` 重启加载器。

## 5. SFC 三部曲选择页背景（2026-10-18，用户报告"背景图片没显示"）

- 该页在主程序里（x2.1 加入）。r150 追踪帧 3400（`--debug-frame`）：第 1–2 个 draw 画背景（512×512 P8 贴图 0x81ED7208，贴图转储正确），第 29 个 draw 是全屏四边形：第 0 层**未绑贴图**，颜色 / alpha 都是 MODULATE(texture, diffuse)，顶点色 0xFF10003A（不透明藏青），混合 SRCALPHA/INVSRCALPHA。
- 原规则（`cfg:untex:1`，未绑贴图读作顶点色）→ 整页近乎黑色的深蓝（r144 实测 0x010019）。当时误以为原机上这一层透明、底下另有背景图，于是改出 `cfg:untex:2`（第 0 层未绑读作透明黑）并设为默认（r151 露出灰色花纹）。**这个前提是错的**：用户的 xemu 截图（`xemu-2026-10-18-23-20-51.png`）整页是纯深蓝 0x100050，没有花纹。
- 0x010019 正好是 0x100050 每个通道的平方（16²/255≈1，80²/255≈25）：`cfg:untex:1` 让 MODULATE(texture, diffuse) 变成 diffuse²。`cfg:untex:2` 还让血条填充层消失（用户报告，r152 截图 hp2 / hp4 对照）。
- 现规则 `cfg:untex:3`（默认）：读贴图但未绑贴图的层整层跳过，当前颜色原样传下去（第 0 层即顶点色）。r161：本页四角 0x100050、标题框内 0x000000，与 xemu 逐像素一致。四个案例的对照见 docs/04 §3.14。`cfg:untex:2` 已删除。
