## black-pc 原样构建（`build\blackpc-orig\`，RelWithDebInfo）

- 配置：`cmake -S ngb-recomp-native/loader -B build/blackpc-orig -G "Visual Studio 15 2017" -A Win32`，编译器识别为 MSVC 19.16。
- 第一次构建**只有一个错误**：`src/d3d/draw.cpp(687)`：`_AddressOfReturnAddress` 未声明（C3861）。原因：MSVC 14.16 不经 `<windows.h>` 声明该内建函数，新版工具集会。
  C++20 相关的其他内容（CMAKE_CXX_STANDARD 20 → `/std:c++latest`）**全部通过**。
- 修正：`draw.cpp` 加 `#include <intrin.h>`，分支提交 `8ada4ac`（唯一改动）。
- 产物：`black.exe` 2,560 字节、`blackrt.dll` 2,945,536 字节（21:02）。
- `black.exe --info game\x21\default.xbe`：输出与 `black-pc/tools/xbeinfo.py` 的一致（标题、ID、17 段、9 个库、145 导入、入口 0x32B385、size 0xE07000）。
  差别：black-pc 内置的内核序号名表（`src/kernel/kexports.h`）只有 BLACK 用到的名字，x2.1 独有的 **36 个序号显示为 `?`**（5、41、42、62、65、74、81、83、84、85、86、126、127、144、150、156、158、169、170、181、195、228、247、252、253、338、339、344、345、346、347、349、353、355、358、359），
  与计划 §1.3 列出的 36 个一一对应 → 阶段 3 要补名表和实现。

## XbSymbolDatabase CLI（`build\xbsymdb\`）

- 用 VS2017 构建失败：`src/OOVPADatabase/D3D8LTCG_OOVPA.c` 的变参宏在 MSVC 旧预处理器下语法错误（C2059）。不改它的源码。
- 改用便携 clang + Ninja（`-G Ninja -DCMAKE_C_COMPILER=x86_64-w64-mingw32-clang.exe`，Release）：13 步全部成功，`build\xbsymdb\projects\cli\XbSymbolDatabaseCLI.exe`。
- 对 x2.1 运行 `XbSymbolDatabaseCLI.exe game\x21\default.xbe -e` → `work\xbsymbols-x21.txt`，**344 个符号**：
  D3D8 变量 53、D3D8LTCG 函数 101、DSOUND 104、XAPILIB 75、XONLINES 11。
  （对照：BLACK 372 个——D3D8LTCG 115、DSOUND 150、XAPILIB 54、D3D8 变量 53；ngbrecomp 用同一库对原版得到 97 个 D3D 名，其 `d3d_symbols.txt` 列 94 个。）
  XNET、XGRPH、DOLBY、PSFD00 没有命中（数据库不含），阶段 2 另行处理。

## C 盘检查

- 以 20:55 为起点列出 `%LOCALAPPDATA%`、`%APPDATA%`（本机指向 D 盘）、`%TEMP%` 下的新文件：全是用户自己的程序（Chrome、Edge、Copilot、QQ、百度网盘、npm 等）的缓存，
  以及 PowerShell 自己的 `StartupProfileData-NonInteractive`；`%TEMP%` 下 21:01–21:04 的 GUID `.tmp` 经文件头核对是 JPEG / PNG 图片（浏览器 / 聊天软件），与构建无关。
- 结论：构建、下载、运行 `--info` 没有在 C 盘留下项目文件。不能由此推出：MSBuild / VS 自己的日志目录（`%LOCALAPPDATA%\Microsoft\VisualStudio`，被过滤规则排除）完全没动；它属于编译器自身的缓存，与显卡驱动缓存同样不在约束范围内。

## 关口 1 结论

通过：未修改的 black-pc（仅一处头文件适配）在本机可构建；`--info` 能解析 x2.1；库符号工具可用并已跑出 x2.1 的 344 个符号；C 盘无项目写入。
