# 2.2.37.6 验证与结论

日期：2026-11-22。用户实测：60Hz 真全屏，2.2.37.6。

## 结果

```text
主选单  60
CG      30
游戏    60
```

这是修复后的正确结果。

## 说明

之前的：

```text
主选单约 52
CG 约 24
游戏约 52
```

不是 Present 把游戏拖慢，而是 kernel vblank 事件本身在 16.7ms 和 19–21ms 之间变化，tick 跟着它走。

2.2.37.6 把 60Hz 真全屏的 tick 改成固定 59.94Hz timer 后：

- 游戏 tick 不再跟 kernel vblank；
- 主选单 / CG / 游戏都按各自应有的帧数运行；
- Present 不需要为这个症状解耦。

## 结论

- 当前问题的根因是 **tick 跟 display vblank 耦合**，不是 Present 耦合。
- Presenter / frame pacing 对「52 / 24」这个症状不是必需。
- 只有出现新的呈现问题（撕裂、帧节奏不匀、CG / 菜单稀疏 Present）时，才需要继续做 Presenter。

## 仍存在的取舍

- 垂直同步关：可能撕裂；
- 垂直同步开：可能多等刷新；
- 高刷 Alt+Enter / 模式切换仍有独立风险；
- 这些是呈现 / 模式问题，不是 tick 问题。

## 2.2.37.7 补充

2.2.37.6 的 `near_60` 每 300 tick 才更新。高刷 + `exclusive_60hz=1` 从 60Hz 真全屏回窗口时，可能短暂选到 165Hz DwmFlush。

2.2.37.7 在 `host3d::exclusive()` 一变化时立刻重查 `near_60`。

实测 Alt+Enter：

```text
host: Alt+Enter ...
vblank: source DwmFlush (window)
host: windowed

host: Alt+Enter ...
host: fullscreen ... (exclusive)
vblank: source 59.94 Hz timer (exclusive)
```

来源在同一时间点切换，不再等 300 tick。
