## 6. XBE 头区域的运行期引用（E 节）与 PE 头副本的位置

游戏 / XAPI / XONLINE 运行期读的头字段：`0x10108`（头长）、`0x10118`（证书地址 → 证书在 0x10184）、`0x1011C`（段数）、`0x10120`（段头表 0x10B00）、`0x10124`（init flags）、`0x10130/134/138`（PE 栈 / 堆大小）。
D3D 段里对 0x10010/0x10020/0x10030 的引用是立即数（寄存器常量），不是读头。**RSA 签名区 0x10004–0x10104 没有任何引用**（black-pc 把 `e_lfanew` 放在 0x1003C 的做法成立）。

NT 头副本的候选位置（都没有代码引用，xrefs.json 核过）：
1. **`.XTLID` 尾到 `HANZI` 之间 0xDC6BB0–0xDC7000，1,104 字节**（首选：能放 0xF8 字节 NT 头 + 最多 0x15 个段头；`.XTLID` 不预载，按需 `XeLoadSection` 只写它自己的 0x710 字节）；
2. 头尾空隙 0x10EC4–0x11000（316 字节）：只够 NT 头 + 1 个段头，要把桩程序合并成单段；
3. 签名区内（256 字节）：段数写 0，Windows 只读 OptionalHeader 的栈 / 堆字段——未验证，不作首选。

## 7. 游戏对 D3D 库全局的内联访问（F 节）

`.text` 直接读写 D3D 段里 **109 个非函数地址**（LTCG 内联），最多的：`0x3D83D0` 脏标志 1,669 处、`0x3D83C8` `D3D_g_pDevice` 172、`0x3D84C4`…`0x3D85D4` 一带（延迟渲染状态数组，`D3D_g_DeferredRenderState` 0x3D8548 在其中）、`0x3D5D10`…`0x3D5EE4`（`D3D_g_DeferredTextureState` 起的贴图状态数组）、`0x3D9278`–`0x3D928C`、`0x3D9588`/`0x3D958C`。
→ 与 BLACK 一样，HLE 必须保留这块内存并在绘制时读 Xbox 侧的状态；数组基址与索引在阶段 4 从 `SetRenderState_*` 各函数的反汇编核出（XbSymbolDatabase 给了 53 个 `D3DRS_*` 变量地址作锚点）。

## 9. 启动路径相关的调用链（`functions.json` 的 called_by 回溯）

- **XNET / XONLINE**：`XNetStartup`、`WSAStartup` 只被 0x300BA0 ← 0x2FF8D0 ← 0x2FF770 调用；0x2FF770 没有直接调用者（经函数指针），读 `[0xDB9A64]`/`[0xDB9984]` 等游戏全局 → 是游戏的在线模块（Ranking）初始化，不是 XAPI 启动序列。`XOnlineLogon` 经 0x301100 ← 0x302180/0x3022D0/0x302430/0x302560。
  推断：不进 Ranking 就不会初始化网络；阶段 3 用内核日志验证，验证前不下结论。
- **XAPI 的 `cli`/`sti`（0x32CCCB ← `mainXapiStartup`）**：函数先读 `XboxKrnlVersion` 的 build 字段并与 0xF68 / 0xFC2 / 0xFC7（3944 / 4034 / 4039）比较，`cli`/`sti` 在旧内核分支里。
  BLACK 用同一版 XAPILIB（5849 qfe 1），black-pc 没有任何特权指令模拟（只在崩溃信息里命名 `PRIVILEGED_INSTRUCTION`）却跑通了，说明报告的内核版本（加载器 `k_misc.cpp` 实为 5838，2026-10-19 证据盘点更正；与 5849 同样大于 4039）时不走该分支。黑之章预期相同。
- **游戏代码的 `wbinvd`（0x31E13E，函数 0x31E0D0）**：先调 `D3D_BlockOnResource` 再 `wbinvd`（资源刷新），调用链 0x31DBE0 ← 0x31D570 ← 0x19A5B0 ← 0x165B30 / 0x16AD40 / 0x17B5E0 / 0x1882D0，**在正常游戏路径上可达**（路线 A 冒烟测试未走到）。
  处理：加载器的向量化异常处理器把 `wbinvd` / `invd` / `cli` / `sti` 当作空操作跳过（用户态下语义等价，比逐处改字节更稳），并记录命中次数。
- **0x30E140**：直接写设备 +0x1DC0、调 0x30E580（含 rdtsc），没有直接调用者（经函数指针，疑似渲染线程 / 帧同步）。阶段 3 日志确认。
- **`RunPushBuffer`** 6 个调用者（0x1D2040、0x1D45C0、0x24D850、0x2BE710、0x30BCA0、0x30C110）大多经函数指针到达；推送缓冲对象从何而来（`CreatePushBuffer`/`BeginPushBuffer` 不在 86 个被调用的 D3D 目标里）尚未查明。
