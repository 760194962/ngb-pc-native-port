# 10 水面与热气清晰度修复（1.1.7-t）

## 现象

用户报告：水面、雾气、热气覆盖人物时，人物边缘出现明显马赛克/狗牙；从水下往上看时水面颜色缺失。最初怀疑 1.1.0 从 Direct3D 9 改为 9Ex 导致。

## 排除的过程

- `8056854`（2026-10-22，0.1.0 前）水面正常；`v1.0.0` 水面坏。
- 单独跑 1.0.1（D3D9，非 9Ex）：水面同样坏 → 不是 9Ex。
- `cfg:zview8:1`（8 位深度视图）无变化 → 不是 R32F 深度视图。
- `D3DSWAPEFFECT_DISCARD` 交换链测试无变化 → 不是 9Ex 的 COPY 语义。
- `8056854..v1.0.0` 之间唯一直接影响小缓冲的是 `ec67b02`（光晕修复）。

## 根因

`ec67b02` 为修夜景光晕，把被大画面写入的小缓冲固定成 Xbox 尺寸，并加 `reduced_rt` / `softened_rt`。水面/热气也走同一套：

```text
[effect] mark target 256x256 src 720x480: 0x002d01e0 ...
```

整屏 720×480 被写进 256×256，再被水面/热气采样；256×256 被压到 1×，人物边缘就被放大成马赛克。

## 修法（1.1.7-t）

- 256×256 这条屏幕拷贝不再进入 Xbox 尺寸路径，按渲染倍率走；
- 只保留光晕最后两步 `256×128`、`128×128` 的 Xbox 尺寸 + 软化；
- 水面写入调用 `0x002D01E0` 再作一次保护，避免它误入光晕的小缓冲路径。

> 1.1.9 更正：`0x002D01E0` 在 x2.1 镜像里是 `mov ecx,[esp+180h]` 的最后一个字节（附近的 call 返回到 `0x2D01CF`、
> `0x2D01E8`），不可能是返回地址，这道保护从未生效；另外 `reduced_rt` 也要求源是光晕尺寸，光晕链的「先平均再缩小」
> 因此一次都没做，这就是文档 11 记的「光柱光晕抖」。1.1.9 的改法见下文「1.1.9：按用途认光晕链」。

没有全局关闭 `ec67b02`，所以光晕修复仍保留大部分。

## 验证

- 用户在同一水面存档对比 `8056854`：1.1.7-t “舒服多了”，水面人物边缘明显恢复。
- 待办：夜景灯光/刀光/盔甲高光再验收一次，确认光晕没有闪烁、重影或硬条纹；其他水面/热气场景（21:9、Boss 场景）抽测。

## 风险与后续

- 这是按缓冲尺寸与调用地址的定点修复，不是最终架构；
- 如果以后有别的效果复用 256×256，可能仍会被影响；
- 更彻底的方案是把水面/热气与光晕拆成两张独立 host 缓冲（B 方案），第一次实现读写顺序错误导致黑屏，暂不采用。

## 1.1.9：按用途认光晕链（`910c615`）

- 证据：水面关卡日志（`run\r037_water`、`run\r044_water_010`）里两张 256×256 是不同的内存：`0x02cd8000`（屏幕拷贝）
  与 `0x02d38000`（被画进 256×128 的光晕链）；另一关（`run\cmp_fix`）光晕链在 `0x015e5000`。所以不需要 B 方案的
  「一块内存拆两份」，但地址随关卡变，不能写死。
- 规则：被画进更小缓冲的「屏幕拷贝」（自身由更大的缓冲画来）之后的那一张开始光晕链（256×128），链上往下画的也入链
  （128×128），保持 Xbox 尺寸并软化；屏幕拷贝本身（256×256、热气的 512×256）保持渲染倍率，被画进 1 倍缓冲时先盒式
  平均到 Xbox 尺寸（`reduced_rt`）。删掉尺寸名单与 `0x002D01E0`。
- 性能（集显，第一章基准）：先试过让 256×256 也入链（平均整张 2880×1440 画面），4 组交替 A/B 比 1.1.8-t 慢 0.36 ms，
  不采用；现方案 `r634` / `r635` 中位数 8.38 / 8.48 ms，1.1.8-t 为 8.05–8.63 ms。
- 用户实机（集显）：水面/热气后的人物、光柱与龙头光晕（不再抖）、夜景灯光、刀光、换关后的光晕都正常。
