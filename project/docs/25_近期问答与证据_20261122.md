## 二、2.2.37.7：Alt+Enter 立即重查 display-60

问题：

- `near_60` 每 300 tick 才更新；
- 高刷 + `exclusive_60hz=1` 从 60Hz 真全屏回 165Hz 窗口时，可能短暂选到 `DwmFlush`；
- 在最多 300 tick 内，tick 可能跟 165Hz。

修复：

```text
host3d::exclusive() 一变化
→ 立刻 near_60 = display_near_60()
→ 再 follow_dwm()
```

实测：

```text
3.816  host: Alt+Enter ...
3.825  vblank: source DwmFlush (window)
3.913  host: windowed

6.979  host: Alt+Enter ...
6.981  host: fullscreen ... (exclusive)
6.985  vblank: source 59.94 Hz timer (exclusive)
```

来源在同一时间点切换。

版本：2.2.37.7，两个仓库均已发布，Latest。

## 三、follow_dwm 重构

把两值 `enum Source` 收成 bool policy：

```text
follow_dwm =
    固定游戏速度关
    且不是独佔
    且显示 59–61Hz
    且 DwmFlush 可用
```

主循环：

```text
if (follow_dwm && DwmFlush 成功)
    DwmFlush
else
    timer
```

验证：

```text
60Hz 真全屏：source 59.94 Hz timer (exclusive)
窗口 60Hz：source DwmFlush (window)
```

和重构前一致。

commit：

```text
929200e refactor: collapse vblank source to a follow_dwm policy
```

## 四、SFC 音量调查

### 来源更正

黑之章原版没有 SFC 三部曲。  
SFC 程序来自《忍者龙剑传 2004》，是用户改镜像加进去的，不是黑之章自带。

### 日志证据

SFC 程序 `NinjaFCJ`：

```text
CreateSoundBuffer(flags 0x100, 25600 bytes, 2ch 32000Hz 16bit, 0 mix bins)
Voice_SetVolume(..., -443)
mixer: 1 buffers, 0 streams playing, peak 0.06–0.11
```

代码路径：

```text
volume -4.43 dB
2D voice headroom -6.00 dB
mix bin 0/1 headroom -6.00 dB
总计约 -16.43 dB
```

主游戏日志：

```text
SetMixBinHeadroom: bin 0..10 headroom 0 (was 1)
```

所以 SFC 比主游戏多衰减 6 dB。

### 测试 +6 dB

只对 `NinjaFCJ` / `NinjaFCU` 把 bin headroom 0–10 设 0。

改后：

```text
[dsound] SFC program: mix-bin headroom 0-10 set to 0 (main-game level)
mixer peak 0.198
```

主游戏同段 peak 约 0.208。

### 用户听感

- 捡到道具的音效确实变大；
- 游戏内挥砍和 BGM 仍然很小。

### 结论

SFC 只有一个 2D buffer，BGM / 挥砍 / 道具都是 SFC 程式先混进同一个 buffer，HLE 再套一次全域增益。

所以：

- +6 dB 证明 HLE 增益生效；
- BGM / 挥砍仍小，代表它们在 SFC 程式内部混音时本来就低；
- HLE 只有一个全域增益，无法只放大 BGM / 挥砍；
- 再全域加 6 dB 会让道具音效过大，可能破音。

要分轨，必须在 SFC 程式混音前处理，目前 HLE 做不到。先看 SFC 自己的 OPTION 是否有 BGM / SE 音量。
