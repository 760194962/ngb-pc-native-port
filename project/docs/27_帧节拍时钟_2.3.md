# 2.3 帧节拍时钟（frame_clock）

日期：2026-11-26。分支 `release-2.3`。代码：`loader/src/d3d/frame_clock_model.h`（纯策略，可仿真）、
`loader/src/d3d/frame_clock.cpp`（系统层）、`tools/clock_sim.cpp`（仿真）、`tools/frame_dup.cpp`（屏幕读帧号）。

## 一、要解决的问题

游戏逻辑是固定步长：一个 Xbox vblank 推进一帧。画面要“丝滑”，每一帧在屏幕上停留的刷新次数必须完全相同。

2.2 的时钟：

| 模式 | tick 来源 | 结果 |
|---|---|---|
| 窗口 / 无边框，60 Hz | DwmFlush（等合成器） | 锁在屏幕上，顺；返回时刻抖动 0.86–5.2 ms |
| 真全屏 60 Hz | 固定 59.94 Hz 计时器 | 屏幕 60.008 Hz，约每 14 秒一帧显示两次，跨边界时连续几次 |
| 其他刷新率 | 固定 59.94 Hz 计时器 | 120/240 Hz 同样周期性重复；144/165 Hz 本质上不可能均匀 |

两个时钟（游戏 59.94、屏幕 60.008）各走各的，重复帧是必然的，不是 bug 能修掉的。

## 二、业界做法与我们的选择

- 现代 3A：逻辑用可变 dt，渲染跟着屏幕走（或 VRR 让屏幕跟着游戏）。我们的游戏是原版 Xbox 固定步长，不能改逻辑。
- 模拟器（RetroArch 的 dynamic rate control、各家的 “sync to display”）：把内容帧率**微调**到屏幕刷新率（千分之几），声音单独处理。
- 我们：tick 仍是计时器，**永不等待屏幕**；但当屏幕刷新率是 ~60 Hz 的整数倍时，把计时器的周期和相位微调到屏幕的 vblank 上（周期限制在 59.70–60.30 Hz，单步变化 ≤0.4%）。显示信息只能“拨”计时器，不能“拦”计时器。

## 三、结构

```text
vblank_thread (device.cpp)          只做 Xbox 的事：计数、vblank 事件、游戏回调
  └─ frame_clock::Ticker            何时 tick
       ├─ Display                   QueryDisplayConfig：精确刷新率（分数）、总行数/可见行数
       │                            D3DKMTGetScanLine：当前扫描线（不等待，约 60 µs）
       ├─ CompositorTiming          DwmGetCompositionTimingInfo 的上次 vblank（不等待；真全屏下也更新）
       ├─ Clock (model)             两张 Grid（扫描线、合成器各一张）；跟随稳定的那张，扫描线优先；
       │                            PI 环把 tick 放到 vblank 后固定相位
       ├─ Sleeper                   高精度可等待计时器 + 最后 0.3 ms 自旋（不再用 Sleep(0) 空转）
       └─ CompositorKeeper          跟随时在窗口/无边框下用独立线程循环 DwmFlush，让合成器每次刷新都工作
```

### 策略（frame_clock_model.h）

- **能跟随的屏幕**：刷新率 R，k = round(59.94/(1/R))，R/k 落在 59.70–60.30 Hz（60、59.94、60.1、120、180、240、360…）。
- **相位**：tick 落在 vblank 开始后 `min(2 ms, 0.12 × 刷新周期)`：60 Hz 2 ms，120 Hz 1 ms，240 Hz 0.5 ms。
  tick 之后只剩最后的拷贝和 Present（游戏在 Swap 里等 tick 之前已经画完），帧总能赶在下一次锁存之前。
- **PI 环**：Kp 0.1、Ki 0.0025，临界阻尼（极点 0.95，约 20 tick 收敛）；从半个刷新周期拉入约 2 秒。
- **网格**：读数 (t, line) → 该帧开始时刻 t − line·p/vtotal；容差 250 µs；连续 8 次不在网格上就重建；最近 64 次至少 62 次命中、
  且最近 1 秒内有命中，才算稳定。读数在一个 tick 内轮换位置，避免长消隐期的模式（165 Hz 面板的 60 Hz 模式消隐占 60% 以上）一直读到消隐。
- **VRR（屏幕跟着我们刷新）**：跟随后相位误差 4 秒降不下来，或周期顶在上下限 4 秒 → 判为 VRR，改回固定 59.94 Hz，60 秒后再试。
- **不能跟随**（75/144/165 Hz、50 Hz、读不到、`timer_vblank`、`--background`）：固定 59.94 Hz，和 2.2 一样。

### 两个相位来源

扫描线在计数器线性时最准（拟合误差 3 µs）。但同一台笔记本在一次真全屏切模式之后，计数器改为数 1200 行源行号、然后直接跳到 1608，
只有 0–15% 的读数落在网格上（窗口和真全屏都一样）。合成器的 vblank 时间戳是软件时间戳，中位偏差 100–130 µs，但 94–98% 在 250 µs 内，
而且真全屏下照样更新（探针 scratchpad `clock\srcprobe.cpp`；翻页统计 GetPresentStats 在这台机器上一律失败，内核 vblank 事件只有 68–77%）。

所以两个来源各拟合一张网格（容差：扫描线 250 µs，合成器 500 µs；合成器的同一时间戳只用一次，停住的时钟不能让网格“活着”）。
进入跟随要求网格稳定（最近 64 次至少 62 次命中），跟随中只要求网格没重建、1 秒内有命中；扫描线稳定时优先用它。

### 真全屏的模式选择（host.cpp exclusive_mode）

开垂直同步 + `exclusive_60hz`：桌面刷新率能跟随（59–61、119–121、239–241…）就保留，不再切换（切模式要黑屏约 1.5 秒）；
否则（144/165 Hz）切到同分辨率的 60 Hz（和 2.2.34 起一样）。

## 四、避开的坑

| 以前的坑 | 这次怎么避开 |
|---|---|
| 2.2.35：tick 等屏幕的 n 次刷新，VRR 下变 24/40/80 帧 | 永不等待屏幕；周期被夹在 59.70–60.30 Hz；VRR 检测后回固定时钟 |
| 2.2.37.5：tick 跟内核 vblank 事件，事件在 16.7 和 19–21 ms 之间跳，菜单 52 帧 | 不用等待式的 vblank 事件，只读扫描线（瞬时值） |
| Sleep(0) 自旋：TIME_CRITICAL 线程只让同级，饿死同核的 CG 解码线程 | 高精度可等待计时器，自旋只剩 0.3 ms，用 pause 指令 |
| DWM 空闲：30 fps 的 CG 每隔一次刷新才来一帧，DWM 偶尔晚一拍 | 跟随时用独立线程循环 DwmFlush（2.2 的 tick 本身就是 DwmFlush，所以以前没暴露） |
| `--background` 的真全屏测试在 60 Hz 下无效 | 测试用前台运行；性能 A/B 用 `--display-vblank` 走跟随路径 |

## 五、验证

### 仿真（tools/clock_sim.cpp，120 秒，读数时间 ±40 µs 噪声，1% 慢帧）

不均匀帧（每帧停留刷新次数不等于主流值）：

| 屏幕 | 2.3 | 2.2 固定 59.94 |
|---|---|---|
| 60.008 / 60 / 59.94 / 59.951 / 60.1 Hz | 0 | 116–301 |
| 165 Hz 面板上的 60 Hz（长消隐） | 0 | 285–293 |
| 119.88 / 120 Hz | 116–118（只剩模拟的慢帧） | 116–553 |
| 180 / 240 / 360 Hz | 118–358 | 755–1392 |
| 144 / 165 / 75 / 100 / 50 Hz | 不变（本质上不能均匀） | 同左 |
| VRR | 固定 59.94，不变 | 同左 |

### 实机（RTX 3060 独显直连，60.008 Hz 面板，桌面 1920×1200，攻略演示 150 秒，屏幕上读帧号）

| 模式 | 2.2.37.13 | 2.3 |
|---|---|---|
| 窗口 | 重复 178 / 219、跳 0 / 1（2 轮） | 重复 144、跳 3（最终版）；CG 段每帧都是 2 次刷新，与基线一致 |
| 无边框 | 开头 4 秒内重复 29、跳 27、成对 44 | 重复 0、跳 0（2 轮） |
| 窗口，读不到扫描线（`--no-scanline`，走合成器时序） | — | 重复 214、跳 1，CG 段规整 |
| 真全屏（vsync，60 Hz） | 重复 66 / 69，含约每 14 秒一次的周期性重复（每轮 9–10 次） | 重复 6 / 26，没有周期性重复；剩下的在开头拉入阶段和演示内容的同一处 |
| 无边框（双来源版） | — | 重复 0、跳 0 |
| 窗口（双来源版，扫描线失真时） | — | 跟随合成器，游戏画面只有开头 2 次，CG 规整 |

“重复”绝大部分是 33–54 秒的 30 fps CG（每帧本来就停 2 次刷新，dup_sum 只排除了一部分）；游戏画面部分新旧都只有零星几次。
窗口 60 Hz 在 2.2 本来就锁着屏幕（DwmFlush），目标是“不倒退”；2.3 的意义在于真全屏、无边框和 120/240 Hz。

跟随状态的日志（每分钟）：相位误差中位 2–5 µs、99% 9–62 µs；tick 唤醒迟到中位 9–80 µs、99% 0.5–0.65 ms。第一分钟的大误差是开头约 2 秒的拉入。

### 性能（RTX 3060 独显直连，攻略演示，跟随路径 `--display-vblank`，4+4 轮交替）

| | 速度 | 平均帧 | p90 | p99 | 慢 draw call |
|---|---|---|---|---|---|
| 2.2.37.13 | 93.70% | 3.79 ms | 6.46 | 16.97 | 10.0（5–13） |

## 七、第二轮：剩下几项的调查与决定（2026-11-26 白天）

**测量前提（重要）：** 这一天前半段向日葵远控一直开着（会拖慢 DWM，见记忆 awesun-dwm-slowdown），当时测到的“真全屏下 tick
唤醒晚 3 ms”“DWM 时间戳漂移”“几轮之间差很多”都是它造成的假象。下面的结论以**退出远控后**的一批（`run\clock\cl_*`）为准；全部在
RTX 3060（独显直连）上，集显待测。

### 干净环境的结果（150 秒，屏幕上读帧号）

| 模式 | 2.2.37.13 | 2.3 |
|---|---|---|
| 真全屏 60 Hz（2 轮） | 重复 72 / 51，约每 14 秒一次，CG 段停 3 次刷新 36 / 24 次 | 重复 3 / 5，CG 段规整 |
| 165 Hz 桌面 → 真全屏（切 60 Hz） | 重复 56 | 重复 6 |
| 165 Hz 桌面 → 无边框 | 每帧 3、3、3、2 次刷新（本质不匀） | 0（自动切到 60 Hz） |
| 窗口 60 Hz | 重复 2、跳 2 | 重复 1、跳 1 |
| 无边框 60 Hz | 0 | 0 |

tick 唤醒迟到 99%：0.42–0.52 ms（所有模式）。性能 2+2：速度 93.72% / 93.70%，平均帧 3.82 / 3.72 ms。

### 逐项决定

| 项目 | 证据 | 决定 |
|---|---|---|
| Present 拆到独立线程 | Present 中位 0.47–0.53 ms，99% 0.97–1.61 ms（窗口 / 无边框 / 真全屏）；5–15 ms 的十几次全在本拍内（不迟到），读屏无对应重复 | 不做：D3D9 设备不线程安全，拆分要多线程锁，每个 draw call 都付代价，而没有可测收益。集显上再量 |
| Alt+Tab / 切模式 / Reset | 进真全屏时游戏线程被 Reset 挡约 0.5 秒，屏幕本来黑约 1.5 秒；tick 照走，游戏只暂停不快进 | 不改 |
| 长帧 | 攻略演示 160 秒：只有启动时标题加载一帧（~60 ms）和记录器写文件一帧 | 本轮不处理（集显再看） |
| 144/165 Hz 无边框 | 见上表 | **做了**：`display_refresh.cpp`，进无边框且屏幕不能跟随时临时切 60 Hz（`CDS_FULLSCREEN`），离开 / 最小化 / 关闭切回，再显示时再切；开关同 `exclusive_60hz`（启动器“全屏时用 60 Hz”） |
| 时钟周期 | 真全屏下合成器时间戳曾把周期估成 59.984 Hz，tick 跟着漂 | **做了**：周期限制在名义值 ±0.01%（QueryDisplayConfig 的名义值准到几 ppm） |
| tick 相位 | 试过刷新的一半 / 四分之一（为容忍相位误差）；真全屏实测 2 ms 好于 4.2 ms（GPU 在 Present 后还要时间，越早越有余量） | 保持 2 ms（120 Hz 以上按 12%） |
| 游戏核心的 CPU 集合 | 当时为“唤醒晚 3 ms”加的；干净环境下关掉它反而 1 / 1 次，开着 3 / 5 次 | **撤掉**（没有收益，不留代码） |
