# vblank 诊断证据与结论（2026-11-22）

证据：`E:\games\pc\ninja gaiden black hurricane native port\NGB-Hurricane\logs\black.log`，诊断版 `2.2.37.6-t`，60Hz 真全屏、vsync 0、timer_vblank 0。

## 结论

`pre` 约 0.01–0.02ms，`blocked` 几乎等于 `raw`。所以：

- 不是 vblank 执行绪晚醒；
- 不是 Present / GPU 拖住执行绪；
- 是 `D3DKMTWaitForVerticalBlankEvent` 本身在 16.66ms 和 19–21ms 之间变化。

19.4ms 约 51.5Hz，和日志里的 51.7 / 51.0Hz 对得上。

这不是初始化失败，也不是 `timer_vblank` 没开。kernel vblank 事件本身在独佔全屏下不稳定，所以 2.2.37.5 的失败 fallback 不会触发。

## 决定

60Hz 真全屏的 tick 不再依赖 kernel vblank，直接固定 59.94Hz timer。

显示仍然由 Present / 垂直同步负责；kernel vblank 不再作为游戏时间来源。

这会让：

- 游戏内不再被 kernel 的 51–52 拖慢；
- CG / 主选单的 tick 不再被拖慢；
- 和「稳定游戏速度」的效果一致。

CG / 主选单的稀疏 Present 仍然可能需要 Presenter / frame pacing，但不再是 tick 问题。
